## Resolved engineering policies

1. Profile and migration: introduce opt-in `dependency-bundles-v1` independently of image policy. Legacy behavior remains explicitly named/scoped until migration is qualified; never silently reinterpret legacy settings or pretend it implements v1. Conflicting legacy cache/byte-budget/TTL settings under v1 are configuration errors. Default admission is lean; greedy must be explicit and immutable within a session configuration identity. Signed Gateway identity remains unchanged. Explicit standalone single-user identity remains supported only on the existing private loopback contract; no unsigned header identity or anonymous shared cache.
2. Namespace: principal, stable session, repository/workspace, route/model and full parser/compiler/tokenizer/render/budget configuration bind all state. One effective root/workspace scope per v1 namespace initially; duplicate effective roots or a workspace transition fail explicitly rather than choosing/resetting. Genuine new versions of that root may update graph generations. Supporting multi-root composition later requires a new contract, not guesses.
3. References: discover all explicit reachable Markdown references from raw observed source before compilation, resolving relative to the referring directory inside the evidenced workspace. Lexical normalization must never escape that workspace or access the adapter filesystem. Preserve cycles/shared nodes/missing content. For boundaryless bundles resolve relative references only when all possible origins have the same applicable directory; otherwise retain an unresolved-origin candidate. Greedy off-graph members do not expand the governing graph until independently reachable; their content keeps background provenance and cannot acquire root/system authority by co-occurrence.
4. Evidence: parse a bounded literal shell read grammar, never execute observed input. Earn support for every command family and wrapper independently. Complete outer spans and executed member sets are mandatory; internal A/B boundaries are optional. Unknown/partial/truncated output never becomes complete. Recognize wrapped Responses and Chat tool results, call IDs and multi-chunk completion. Exclude command substitution, writing, redirection, heredocs, unexecuted branches, unproved glob membership and misleading global status. A typed unsupported observation preserves the uncertain span and exposes a limitation; do not coach the client into special reads.
5. Versions: ordered bundle members plus exact aggregate digest define independent A, A+B and B+A entries. Unknown individual versions stay unknown. A fresh singleton incompatible with an older boundaryless bundle marks that older bundle stale/conflicting even if equality cannot be disproved; never splice unidentified bytes. Reverse indexes invalidate overlapping entries and versioned graph edges. Deduplicate old call/item occurrences and fingerprints at a monotonic session revision. A deliberate revert requires a genuinely new observed occurrence; ambiguous replay cannot roll state back. Repeated file operands do not inflate slot width.
6. Ownership and RAM: one service worker and one live owner per session in v1; reject unsupported multi-worker configuration. Use a protected ownership lock for checkpoint generation updates. All live graph/index/source-version/compiled/selection/single-flight state lives in Python memory. Normal hits never read/deserialize checkpoint content, including files in /dev/shm. No active-session TTL/LRU or capacity-driven entry eviction. Set explicit configurable process and per-session safety ceilings (initial documented recommendations 512 MiB and 128 MiB); admission pressure returns fixed 503 with existing state preserved. Cleanup is explicit session teardown/authorized retention cleanup, not a hidden eviction loop.
7. Recovery: explicit protected per-session recovery opt-in is mandatory for v1. Retain exact admitted original bundles and provenance, not whole conversations/images/auth headers/unrelated tool output. Directory 0700, file 0600, current owner, no symlink/path escapes. Atomic generation, digests, fsync file and directory before committing a request that newly relies on that generation. A failed checkpoint aborts that transformation. Load only a resumed authenticated session, validate full binding/configuration/schema/integrity, then reconstruct RAM in a new epoch. Recompile needed current bundles lazily once per epoch under bounded concurrency; do not forward with unresolved required entries. Never read recovery originals on normal hits or send them to the main model as hidden fallback. Keep invalid historical originals only as evidence, never current authority. No automatic dormant-session scan/recompile or automatic timed deletion; operator-owned retention and secure storage, with deployment encryption requirements stated explicitly.
8. Sensitive material: the protected evidence/recovery exception covers observed source bundles and derived metadata only. Operational logs/metrics remain content-free. Never store transport credentials or credential-bearing wrappers. Detectable forbidden credentials cause typed rejection/quarantine without logging content; do not silently redact and claim exact fidelity, nor claim complete secret detection. Operators must enable and protect source retention deliberately. Filesystem encryption is a deployment prerequisite where required, not an unimplemented encryption guarantee.
9. Compilation: direct authenticated tool-free nonrecursive upstream channel, treating source as data; max one concurrent compiler leader by default. Single-flight per full key. Compile once per unchanged bundle/version/configuration/live epoch. V1 has no automatic infrastructure/schema/truncation retry: failed/cancelled/truncated/over-budget results are invalid and explicitly reported. Legacy adaptive compiler-v3 behavior stays legacy-scoped. Recovery compilation is separate work with a new epoch/reason; it is not an ordinary cache hit. Compiler semantic output must preserve governing scopes, MUST/MUST_NOT/NEVER, exceptions, conflicts, all deterministic candidates and separate confidence/priority.
10. Token accounting: effective C is explicitly configured from a validated route/session contract, never inferred from the serving maximum or executor profile. Require a pinned CPU-only actual model tokenizer artifact/version/digest; no model weights, torch or image decoding. A new minimal locked tokenizer dependency may be added only in the tokenizer objective. Base slot=floor(C/32), width=distinct represented members, allowance=width*slot. Count final rendered block including references/metadata with that tokenizer. Set aggregate injection limit=floor(C/4) initially; generation reserve defaults to max(4096,floor(C/8)), tool reserve 2048, uncertainty/template reserve 1024, all explicit configurable identity-bound values validated against C. Count remaining ordinary text/tools/structure with the tokenizer and model-envelope policy; image bytes are not text tokens, and any enabled vision route requires an explicit validated per-retained-image reserve. Unknown/mismatched tokenizer/context/vision capability rejects v1 readiness or request; never substitute a byte/character estimator as authoritative.
11. Selection: deterministic root first, then reachable essential binding entries, missing-binding acquisition guidance, then optional entries ranked by priority/current-request relevance and stable identity. Deduplicate coverage where a ready bundle supplies the same current files; prefer the narrower eligible entry when it preserves all required information. Never inject both overlapping entries merely because stored. Priority affects injection, never graph eligibility or admission. Optional omission is whole-entry and observable; required overflow returns typed 422, never truncation or dangling required references. No per-request model ranking call or recompilation due to selection alone.
12. Replacement: pure versioned exact-span edit plans coordinated with session state. Keep tool call IDs/name/arguments/order/status/prefix/suffix, ordinary text, images and API envelopes. Replace evidenced root and eligible read-content spans only after compilation, selection and durable checkpoint preparation succeed. Opaque namespace-bound references identify exact entry/version and are accompanied by usable required compiled content. Keep original source roles/authority explicit in compiled blocks; off-graph greedy content cannot become system instruction. Unknown/forged/cross-session/stale references reject. Replayed originals are replaced again with RAM hits; transformed inputs are idempotent. Endpoint-specific Responses instructions/Chat placement must be tested for authority preservation.
13. Failure: unsupported or uncertain untransformed source may pass unchanged with a fixed observable limitation, without claiming acquisition/replacement. Once an admitted required transformation needs compilation/checkpoint/state, failure rejects/defers with sanitized typed status (503 infrastructure/recovery/resource; 409 version/scope conflict; 422 budget/invalid transform). Never forward dangling virtual references, silently drop governance, load disk originals for the main model, or automatically replay a forwarded request. Disconnect cancels owned upstream work; single-flight followers cannot cancel another request's live leader incorrectly. Auth and image policy remain ordered and independent.
14. Observability: fixed enums/counts/timings, no private filenames/digests/session/cache IDs in metric labels. Distinguish root recognition, actual content acquisition, graph admission, first compilation, RAM hit, source replacement, compiled injection, source-absent injection, actual native compaction, restart recovery and final upstream acceptance. Protected synthetic evidence may correlate exact requests/hashes; no private corpus in Git. Provider usage and client cumulative usage are overlapping separate ledgers, compiler/recovery overhead separately metered.
15. Qualification/publication: focused and full locked gates per meaningful runtime stage; exact Gateway contract and all required CI per PR. Preserve frozen RC10 and historical records. Do not repoint any published record to new source. A development provenance update must truthfully distinguish current development artifacts from RC10; if existing gates make product development require a release, fix the development-state contract in a bounded same-PR continuation without weakening artifact validation. Final stage builds immutable wheel/sdist/source identities and, when supported on disposable infrastructure, image identity; registry publication, benchmark dispatch, deployment and cutover are not authorized by this implementation request. Genuine Codex/model acceptance uses only synthetic tasks and private ephemeral state, exact declared client/tokenizer/model context, serial bounded requests and complete teardown. Missing access is BLOCKED, never acceptance.
